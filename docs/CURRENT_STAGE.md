# 当前阶段

更新日期：2026-09-27。本文件是当前进度的唯一汇总入口。

## 当前目标

维持可操作的单机浏览器演示基线。本轮在既有“员工系统 / 系统管理后台”职责边界上，完成商品、套餐、销售规格和成交价格快照的最小统一模型：日常营业仍在员工系统，`/admin` 增加真实存在的目录、套餐和当前价格维护能力。

本轮没有接入 PostgreSQL、增加生产依赖或修改数据库 schema。运行时仍使用浏览器 `localStorage`，但商品与套餐的运行时唯一事实来源已经收敛为 `state.catalog`；`DEFAULT_CATALOG` 只用于初始化、迁移和恢复 DEMO 数据。

## 当前实现范围

根据现有代码和本轮验证，项目已经覆盖：

- 员工系统 `/` 承载房间、存取酒、报表、“我的”及“待办 / 审核中心”；待办中心只汇总我的待办、待我审核和已处理事项。
- 业务审核入口按挂账、回款、特殊差额、赠酒、房间恢复、库存、客诉及大额报销等具体权限显示，不依赖 `backend.view`，并继续执行 `review.self` 自审限制。
- 系统管理后台 `/admin` 当前承载员工身份与具体权限、商品目录、套餐和当前价格维护，不承载营业审核、库存、客诉、交班或营业报表，也不提供尚未实现的配置占位页。
- 系统管理后台 `/admin` 在 `catalog.manage` 权限下维护已有商品的名称、销售规格当前价格、启停和排序，以及已有房间套餐的名称、总价、基础房费、赠饮参考值、启停和排序；该权限与业务审核权限解耦。
- 员工补录、库存、采购、交班、回款登记等主动发起型营业操作继续位于原业务模块或“我的”。
- 商品以稳定 `id`、`baseUnit` 和 `saleOptions` 表达销售与库存单位；库存按基础单位扣减，当前未增加重复 `sku` 字段。
- 套餐表达房型／时段价格、固定配品和开房赠饮的允许选择范围；套餐不保存 `affectsInventory`，开房订单保存客人最终选择的 `resolvedComponents`，库存按实际组成中的商品属性扣减。
- 增购和后续赠酒订单保存商品、分类、基础单位、销售规格、销售数量、基础数量、成交／参考单价和金额快照；历史报表不重新读取当前目录价格。
- 旧状态迁移保留已有成交金额；历史商品元数据、单价或赠酒参考值无法可靠恢复时标为 `legacy`／未知，不使用迁移当天当前售价伪造。
- 房间、开房、消费、换酒、赠酒、收钱、结账、挂账、预订和存取酒。
- 具体权限、条件自审、房间异常、库存盘点、支出／采购、客诉、交班和员工归属。
- 日／周／月报表、日间／夜间／自动主题。
- 切换演示身份、练习时间和恢复演示数据明确标记为 DEMO / training 工具，不属于正式生产业务功能。
- PostgreSQL 16 关系型设计基线、种子数据和金山营业报表导入映射；尚未接入运行时，本轮保持不变。

业务细节以 [REQUIREMENTS](./REQUIREMENTS.md) 为准，文件入口以 [MODULE_MAP](./MODULE_MAP.md) 为准。

## 未完成范围

### 正式使用前的核心缺口

- 没有业务 API、数据库运行时连接、migration 执行器或服务端事务。
- 没有真实账号、会话、服务端权限、离职禁用和生产审计。
- 没有多设备同步、并发冲突处理、实时刷新和服务器账本。
- 没有真实支付回调、退款／冲正、美团／抖音验券和正式财务对账。
- 没有可靠通知、附件对象存储、自动备份和恢复演练。

### 已知业务缺口

- 退款、撤单、并房、换房、拆账、会员和营销。
- 存酒转赠、过期、损耗审批和跨店存取。
- 商品新增／删除、分类和销售规格结构的完整主数据治理；本轮只维护默认目录中的已有项目和当前价格。
- 正式班次、营业日关账和生产级报表口径。
- 实际金山营业报表尚未导入，只有暂存结构、模板与字段映射。

### 质量与现场验收缺口

- 没有持续集成、自动部署、监控和告警。
- 没有 PostgreSQL 集成测试、API 测试、多设备并发或安全测试。
- 真实手机触控、系统大字体、输入法遮挡、弱网和断网恢复仍需现场验证。

- 用户目标或权威需求存在冲突且无法从现有文档判定。
