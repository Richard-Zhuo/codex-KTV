# 脱岗 MVP P0 业务契约矩阵

状态：2026-09-28 Track B `3193635` 契约，2026-09-29 按 Track A `6aa01ba` 集成候选更新当前实现口径。依据为《脱岗版 MVP 总审计与实施路线图》P0-1 至 P0-8、当前 docs/REQUIREMENTS.md 及本轮代码核查。此矩阵写目标行为，不把演示缺陷升格为需求。29 项能力均属 P0；没有在本轮实施完整功能。逐项测试归属见 [OFFSITE_CONTRACTS](./OFFSITE_CONTRACTS.md)，已知错误见 [KNOWN_ISSUES](./KNOWN_ISSUES.md)，真人和门店阈值见 [OPEN_BUSINESS_DECISIONS](./OPEN_BUSINESS_DECISIONS.md)。

口径：下文 state 指营业业务事实；失败时必须不产生部分订单、付款、库存或房态写入。拒绝操作可以在独立审计通道留拒绝记录。幂等要求针对同一操作键；不同键的并发仍须另做版本/业务约束。金额均为整数分。现有测试指本分支自动测试，未来目标未实现的测试列在缺失项中。测试资源就绪只说明可发起验证，不等于成功证据。

## 01 共享可信账本

- 业务能力：共享可信账本
- 当前行为：server.js 只供静态页面；营业状态在单浏览器 localStorage。
- 脱岗目标行为：现场与远程读取同一可信账本；版本冲突、重复命令及并发开房由受信任事务裁决。
- 前置条件：正式数据源、网络及迁移核对完成。
- 允许操作人：已认证且拥有动作权限的账号。
- 输入：账号、操作键、期望版本、动作与业务输入。
- 成功结果：相关订单、付款、库存、房态和审计原子提交；其他设备读到同一版本。
- 必须留下的记录：命令结果、版本、操作者、时间、业务引用及审计。
- 失败条件：身份不明、版本冲突、重复键内容冲突、服务不可用。
- 失败后 state 是否必须完全不变：是；业务 state 原子不变，允许独立拒绝审计。
- 幂等要求：同一操作键至多生效一次；重复请求复用原结果。
- 资金影响：以已提交付款事件为准。
- 库存影响：以已提交库存事件为准。
- 房态影响：同一房仅一笔成功占用。
- 报表影响：只读已提交事件和快照。
- 需要的审批：动作本身有审批要求时执行。
- 异常停止点：账本不可读或状态不明时停止新交易。
- 当前代码是否已经支持：否；SQL 是设计基线。
- 现有测试覆盖：entry.test.js、database.test.js 只查静态边界；offsite.contract.test.js 测本机操作键。
- 缺失测试：双设备一致性、并发冲突、持久幂等、断线重试与迁移核对。

## 02 真人账号与最小权限

- 业务能力：真人账号与最小权限
- 当前行为：演示身份可任意切换；capabilities 仅保存在本机。
- 脱岗目标行为：真人账号唯一归属、每班可营业、按动作最小授权；服务端重新鉴权。
- 前置条件：门店确认实名映射、值班安排和替补。
- 允许操作人：账户本人；授权管理员调整权限。
- 输入：认证凭据、权限变更理由及版本。
- 成功结果：每笔交易显示实际操作者，越权调用被拒。
- 必须留下的记录：账号、授权变更前后、操作者、原因、时间。
- 失败条件：借号、失效账号、无具体权限、自审缺额外权限。
- 失败后 state 是否必须完全不变：是；业务 state 原子不变，允许独立拒绝审计。
- 幂等要求：同一操作键至多生效一次；重复请求复用原结果。
- 资金影响：越权不得记钱。
- 库存影响：越权不得改库。
- 房态影响：越权不得改房态。
- 报表影响：按授权可见，不把入口权当审核权。
- 需要的审批：高风险授权按门店决定。
- 异常停止点：无法证明真实账号归属时停止有资金和库存影响的操作。
- 当前代码是否已经支持：部分；演示权限检查存在，认证不存在。
- 现有测试覆盖：rules.test.js 与 offsite.contract.test.js 覆盖具体权限、backend.view、自审。
- 缺失测试：真人登录、跨设备鉴权、权限变更审计、排班可操作性。

## 03 房间和订单生命周期

- 业务能力：房间和订单生命周期
- 当前行为：九间房、预订、开房、待清洁；订单 kind 为 room 或 retail。
- 脱岗目标行为：房态与订单引用一致；故障房不可售；游离旧单可处置；零售不占房。
- 前置条件：房间可用、时段开放、商品及套餐有效。
- 允许操作人：具有 room.open、room.clean 等具体权限者。
- 输入：房号、渠道、套餐选择、操作键和预期房态。
- 成功结果：只生成一单；营业房指向房单；结账后转待清洁。
- 必须留下的记录：订单状态链、房态变化、实际操作者、时间、原因。
- 失败条件：已占房、故障、时段关闭、脏房未确认。
- 失败后 state 是否必须完全不变：是；业务 state 原子不变，允许独立拒绝审计。
- 幂等要求：同一操作键至多生效一次；重复请求复用原结果。
- 资金影响：开房形成应收，不自动等于实收。
- 库存影响：赠饮按实配数量扣或明确未计账。
- 房态影响：房单占房；retail.room 必须为 null。
- 报表影响：房单与零售分列并合并营业汇总。
- 需要的审批：故障恢复；脏房例外规则待定。
- 异常停止点：旧单和新房引用无法判定时停止房态修改。
- 当前代码是否已经支持：部分。
- 现有测试覆盖：rules.test.js、retail.test.js、offsite.contract.test.js 覆盖房单/零售和房态。
- 缺失测试：多设备同房竞争、游离单完整处置、房态异常演练。

## 04 套餐金额一致性

- 业务能力：套餐金额一致性
- 当前行为：单机演示已拒绝总价与分项不一致的套餐更新、旧状态加载与报价；正式价格审批和版本仍缺。
- 脱岗目标行为：套餐总价等于基础房费加赠饮参考值；报价、订单应收与结账口径一致。
- 前置条件：套餐版本有效，当前价格经审核生效。
- 允许操作人：有 catalog.manage 的价格维护人；最终审批人待确认。
- 输入：套餐 ID、价格分项、总价、生效时间及原因。
- 成功结果：不等式配置被拒；历史订单价格快照不变。
- 必须留下的记录：价格版本、变更前后、审批与订单快照。
- 失败条件：总价不等于分项、负值、过期版本。
- 失败后 state 是否必须完全不变：是；业务 state 原子不变，允许独立拒绝审计。
- 幂等要求：同一操作键至多生效一次；重复请求复用原结果。
- 资金影响：仅新开单取新价。
- 库存影响：赠饮数量独立于金额。
- 房态影响：无直接。
- 报表影响：历史只用成交快照。
- 需要的审批：正式改价审批规则待确认。
- 异常停止点：报价与应收不等立即暂停该套餐开房。
- 当前代码是否已经支持：演示金额一致性已修，正式价格生命周期仍未支持。
- 现有测试覆盖：bugs-evidence.test.js、offsite.contract.test.js、persistence.test.js 的修复后断言。
- 缺失测试：并发改价、正式审批及生效时间。

## 05 收款

- 业务能力：收款
- 当前行为：手工选择渠道和整数分；collect/settle 验金额，无外部到账证明。
- 脱岗目标行为：记录实际到账凭据、付款身份和发生时间；应收与实收分开。
- 前置条件：有效待收费用、真实到账已核实。
- 允许操作人：当班有 payment.collect 或 payment.settle 权限者。
- 输入：原单、费用、渠道、金额、外部凭据、操作键。
- 成功结果：付款一次入账，余额按确认付款减少。
- 必须留下的记录：稳定付款 ID、原单与费用引用、渠道、金额、发生时间、操作者和凭据。
- 失败条件：金额不符、重复凭据、无权、未到账。
- 失败后 state 是否必须完全不变：是；业务 state 原子不变，允许独立拒绝审计。
- 幂等要求：同一操作键至多生效一次；重复请求复用原结果。
- 资金影响：净实收只计有效付款，退款独立扣减。
- 库存影响：无直接。
- 房态影响：收钱后仍营业；结账完成释放。
- 报表影响：销售与资金发生日分别呈现。
- 需要的审批：异常付款修正需冲正审批。
- 异常停止点：无法核实到账时不得标记已收。
- 当前代码是否已经支持：部分；手工记录可用，真实核验缺失。
- 现有测试覆盖：rules.test.js、offsite.contract.test.js 多笔付款。
- 缺失测试：真实凭据、付款 ID、跨日归属、重复提交持久性。

## 06 多笔付款

- 业务能力：多笔付款
- 当前行为：同一订单 payments 数组可多渠道、分次收，单笔无稳定 ID。
- 脱岗目标行为：每笔付款可唯一引用并支持后续退款、冲正及逐渠道核对。
- 前置条件：订单有效、待收费用和每笔到账明确。
- 允许操作人：收银授权账号。
- 输入：每行渠道、金额、费用引用及操作键。
- 成功结果：每笔独立保留，合计等于本次应收，重试不新增。
- 必须留下的记录：各付款 ID、费用/订单引用、时间、渠道、金额和操作者。
- 失败条件：合计不符、无效渠道、同键变更内容。
- 失败后 state 是否必须完全不变：是；业务 state 原子不变，允许独立拒绝审计。
- 幂等要求：同一操作键至多生效一次；重复请求复用原结果。
- 资金影响：付款合计组成总实收。
- 库存影响：无直接。
- 房态影响：collect 不释放房；settle 才释放。
- 报表影响：原付款逐渠道、按资金发生时间归集。
- 需要的审批：原付款本身无；反向交易另定。
- 异常停止点：无法辨认目标付款时停退款/冲正。
- 当前代码是否已经支持：部分。
- 现有测试覆盖：rules.test.js、offsite.contract.test.js 四笔跨操作付款与重试。
- 缺失测试：稳定 payment ID、部分退款上限、付款级并发。

## 07 免零／差额

- 业务能力：免零／差额
- 当前行为：结账少收默认任意金额免零；特殊情况待审但单已关闭。
- 脱岗目标行为：免零限门店批准的小额；大额须事前审批或维持待收，不得伪装实收。
- 前置条件：原应收、已付、差额和理由确定。
- 允许操作人：收银可发起；超限由指定审核人批准。
- 输入：订单、实收、差额类型、理由及审批。
- 成功结果：应收、免零和净实收可分解复核。
- 必须留下的记录：原应收、付款、免零金额、理由、审核人及时间。
- 失败条件：超限无审批、金额失配、理由空缺。
- 失败后 state 是否必须完全不变：是；业务 state 原子不变，允许独立拒绝审计。
- 幂等要求：同一操作键至多生效一次；重复请求复用原结果。
- 资金影响：免零减少应收，不增加实收。
- 库存影响：无直接。
- 房态影响：仅合法结账释放房。
- 报表影响：免零与现金收入分列。
- 需要的审批：门店确认自动上限和超限审批人。
- 异常停止点：只收极小金额却拟结清时暂停。
- 当前代码是否已经支持：否；已复现高额免零。
- 现有测试覆盖：rules.test.js 的正常免零路径；offsite.contract.test.js 的 168 元/0.01 元错误复现已跳过，不作通过证据。
- 缺失测试：未来限额拒绝、审批前房态和余额。

## 08 平台券

- 业务能力：平台券
- 当前行为：美团/抖音开房计零元，同时 voucher.status 为待验券。
- 脱岗目标行为：人工或接口核销凭据可追；未核券不能成为已覆盖的正式资金事实。
- 前置条件：券来源、号码和核销结果可核验。
- 允许操作人：收银/验券授权现场账号。
- 输入：平台、券引用、核销凭据及时间。
- 成功结果：券覆盖额单独入账；后续增购正常计价。
- 必须留下的记录：原单、券 ID、平台、核销证据、操作者及结果。
- 失败条件：重复核销、过期、验券失败、证据不明。
- 失败后 state 是否必须完全不变：是；业务 state 原子不变，允许独立拒绝审计。
- 幂等要求：同一操作键至多生效一次；重复请求复用原结果。
- 资金影响：券覆盖与现金/线上实收分开。
- 库存影响：赠饮仍按实物扣库。
- 房态影响：未核券的房态处置需明确。
- 报表影响：券覆盖与付款渠道分列。
- 需要的审批：异常券放行人待确认。
- 异常停止点：无法验券时不按已付继续无欠款结算。
- 当前代码是否已经支持：部分；仅待验券占位。
- 现有测试覆盖：rules.test.js 的待验券提前抵房费复现已跳过，不作通过证据。
- 缺失测试：核销门禁、重复券、失败恢复及凭据核对。

## 09 商品销售

- 业务能力：商品销售
- 当前行为：state.catalog 为运行时目录，销售行有稳定商品/规格和成交快照。
- 脱岗目标行为：在售真实 SKU 经核对；房间与零售共用有效性、价格和库存规则。
- 前置条件：商品启用、规格有效、库存已建账且足够。
- 允许操作人：有 order.sale 或 retail.sale 的账号。
- 输入：商品 ID、规格 ID、销售数量、归属员工。
- 成功结果：销售行金额=单价×销售数量，库存基础数量=规格基础量×销售数量。
- 必须留下的记录：商品、名称/分类/价格快照、行 ID、经办和归属。
- 失败条件：未建账、无货、停用、错误价格、无权。
- 失败后 state 是否必须完全不变：是；业务 state 原子不变，允许独立拒绝审计。
- 幂等要求：同一操作键至多生效一次；重复请求复用原结果。
- 资金影响：形成应收；零售要求同时全额收款。
- 库存影响：受管商品按基础单位出库。
- 房态影响：房间加购不改房态；零售不占房。
- 报表影响：旧行只读成交快照。
- 需要的审批：当前价维护流程待定。
- 异常停止点：价格或商品身份不明时停销售。
- 当前代码是否已经支持：演示支持。
- 现有测试覆盖：catalog.test.js、retail.test.js、rules.test.js、offsite.contract.test.js。
- 缺失测试：正式商品初始化、价格版本/审计、服务端并发销售。

## 10 retail

- 输入：销售行、付款行、归属员工及操作键。
- 成功结果：kind=retail、room=null、立即完成；无房态影响。
- 必须留下的记录：订单、行快照、付款、库存流水与操作者。
- 失败条件：任一行或付款失败。

- 库存影响：同一事务出库。
- 房态影响：绝不占房。

- 异常停止点：无法判断真实收钱或库存时停成交。
- 当前代码是否已经支持：演示支持。

- 缺失测试：正式账本和退货/退款。

## 11 库存期初

- 业务能力：库存期初
