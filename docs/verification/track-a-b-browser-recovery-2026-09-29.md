# Track A＋B 隔离浏览器恢复演练（2026-09-29）

## 环境与测试数据

- 分支：`codex/track-a-integration`；在提交前使用当前工作树文件运行。
- 浏览器：Codex 内置浏览器（IAB），只打开本机 `127.0.0.1` 上由系统分配的临时端口；未操作 Chrome、Edge 或原项目常用来源。验收用来源为 `127.0.0.1:63503`，演练结束后关闭页面和服务。
- 夹具：`browser-recovery-harness.mjs` 以 `initialState`、`transact(open)`、`transact(pay)` 生成合成订单 D1；历史套餐成交价和现金付款均为 16800 分。只将**当前** `room.small.night.priceCents` 改为 100 分，制造旧记录套餐价格不一致。首次安装前主存储键为空，夹具拒绝覆盖已有主键。

## 浏览器观察

| 步骤 | 实际结果 |
|---|---|
| 加载异常记录 | 员工入口显示“已暂停保存”，可读历史订单 1 笔、付款 1 笔；普通营业导航不可用。恢复副本与原主键原文相同。 |
| 查看并复制原文 | 展开的只读 `textarea` 与原主键原文一致。浏览器执行全选和复制后，剪贴板内容与只读框逐字相同，共 23288 字符。 |
| 未修正时重新检查 | 点击“重新检查本机记录”后仍显示停写页。 |
| 人工修正 | 在同一隔离来源的第二标签页粘贴所复制原文，逐字匹配主键后，仅把当前套餐价从 100 分修为 `5000 + 11800 = 16800` 分；订单对象未被改动。 |
| 显式重检 | 原员工页收到跨标签页更新后仍停写；点击“重新检查本机记录”才恢复房间页，显示累计实收 ¥168。 |
| 修正后核对 | 主键仍有订单 D1，历史订单对象与修正前逐字相同，付款 1 笔共 16800 分，历史 `packagePriceCents` 16800 分；原始异常原文仍在恢复副本中。 |

验收核对页返回：`orderCount=1`、`historicOrderUnchanged=true`、`historicPackagePriceCents=16800`、`paymentCount=1`、`paidCents=16800`、`currentPackagePriceCents=16800`、`backupMatchesOriginal=true`。

首次检查验证夹具时，修正按钮因夹具将订单数组误与单笔订单比较而拒绝执行，主键未变化；更正夹具后，在全新随机端口来源完整重跑以上流程。此证据来自真实页面交互和合成浏览器存储，不代表正式浏览器数据或生产环境恢复演练。
