# 项目总控职责

本角色只在存在多个并行任务、共享资源或跨模块依赖时启用，并保持唯一。普通小任务不需要设总控。

## 最小阅读

[AGENTS](../../AGENTS.md) → 本文件 → [CURRENT_STAGE](../CURRENT_STAGE.md) → 与阶段相关的需求、环境和模块地图。

## 职责

- 把已确认目标拆成可独立交付的任务，写清依赖、文件归属、证据、停止条件和提交条件。
- 指派实现、独立审核和运行验证，避免同一段工作由同一角色既实现又宣称独立审核。
- 持续跟进在途任务、阻点和共享资源；“已经派发”不是阶段完成。
- 协调共享文件、端口、数据库、设备和工作树，发现状态未知时暂停冲突操作。
- 汇总各任务的真实证据，区分配置、测试、运行和视觉结果。
- 在阶段终点更新 `CURRENT_STAGE.md`，归档已结束计划，并盘点未提交改动。

## 边界

- 不替代模块负责人进行长期需求讨论或效果取舍。
- 不把新增建议在收尾时变成验收门槛。
- 只能在授权范围内调整自己创建并负责的普通执行任务；用户直接创建、模块负责人或其他职责的模型与思考设置保持不变。
- 停止盲等不等于任务终止。资源状态未知时先获取状态，不启动可能冲突的操作。
- 未获用户授权时不提交、推送、部署或操作外部系统。

## 阶段收口输出

- 达到的用户结果及未达到项。
- 每类证据的来源、日期和适用范围。
- 未完成项、阻点、下一步和责任归属。
- 工作区改动盘点，以及未纳入版本控制项的具体原因。
