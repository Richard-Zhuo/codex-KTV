# AI 任务启动模板

模板只引用权威文档，不复制整套规则。按任务规模删减，不机械启用全部角色。

## 实现任务

> 先读 `AGENTS.md`、`docs/CURRENT_STAGE.md`、`docs/REQUIREMENTS.md`，再从 `docs/MODULE_MAP.md` 找到本任务最小代码和测试入口。目标是：〈用户结果〉。非目标：〈明确排除〉。行为用例：〈前置／操作／预期〉。只修改：〈范围〉。需要证据：〈测试／运行／视觉〉。遇到〈停止条件〉时停止并报告。保留现有未提交改动，未经授权不要提交或推送。

## 独立代码审核

> 审核目标：〈提交或改动范围〉。先读 `AGENTS.md`、相关需求和模块地图。只报告会导致错误行为、回归、数据风险或无法验证的问题，并给出文件与稳定符号。检查测试是否覆盖关键用例；不要重复实现，不因缺少可选优化阻止收口。若没有问题，明确说明剩余风险和未取得的证据。

## 运行／视觉验证

> 验证目标：〈行为或页面〉。按 `docs/DEVELOPMENT_ENVIRONMENT.md` 使用项目标准入口。逐个用例记录前置状态、操作、预期和实际证据；区分 HTTP 可达、功能通过和视觉通过。工具失败只记为证据未取得。不要修改产品代码，除非用户另行授权。

## 文档整理

> 先读 `AGENTS.md` 和 `docs/README.md`。把新事实写入唯一维护位置：需求进 `REQUIREMENTS.md`，状态进 `CURRENT_STAGE.md`，命令进 `DEVELOPMENT_ENVIRONMENT.md`，入口进 `MODULE_MAP.md`，架构进 `ARCHITECTURE.md`。历史材料移入 `docs/archive/` 并标记不是当前指令。检查本地链接；不要复制第二套规则。

## 项目总控

> 先读 `docs/roles/PROJECT_CONTROLLER.md` 和当前阶段。把目标拆成独立任务，明确文件归属、依赖、证据、停止和提交条件。持续处理在途任务与共享资源，汇总实现、审核和验证结果；没有用户授权时不提交、推送或部署。
