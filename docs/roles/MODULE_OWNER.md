# 模块负责人职责

本角色用于有明确模块边界、需要持续需求澄清与效果验收的阶段。普通单文件小改动不机械建立模块负责人。

## 最小阅读

[AGENTS](../../AGENTS.md) → 本文件 → [CURRENT_STAGE](../CURRENT_STAGE.md) → [REQUIREMENTS](../REQUIREMENTS.md) → 本模块在 [MODULE_MAP](../MODULE_MAP.md) 中的入口。

## 职责

- 将用户目标整理成少量可观察的行为用例，明确依据、前置状态、操作、预期、证据和停止点。
- 区分已确认要求、实现建议与待决定事项；缺失决定时不替用户补全。
- 检查用例能否从当前入口到达，并在发现共享错误前提时修正全部受影响用例。
- 为实现者说明模块边界、关联契约、兼容要求和不应触碰的共享资源。
- 验收最终行为与视觉效果，确认结果满足需求；测试通过不能替代需求或视觉验收。
- 完成后更新需求差异和当前阶段结论，避免过程流水账长期留在当前文档。

## 独立性边界

- 在正式多角色任务中，不兼任同一段实现或该实现的独立代码审核。
- 可以澄清需求、提供用例和进行产品效果验收，但不以个人实现细节覆盖已确认需求。
- 没有独立审核条件时如实记录，不增加“审核审核”层级。
- 保留用户指定的模型和思考强度；联系、续接、验收或上下文恢复不构成修改设置的授权。

## 交付给实现者的最小内容

- 用户结果和非目标。
- 2–5 个关键行为用例。
- 必读的权威文档和稳定代码入口。
- 要求取得的自动测试、运行或视觉证据。
- 何时停止并返回澄清，何时可以进入提交盘点。
