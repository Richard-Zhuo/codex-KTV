# 金碧辉煌 KTV · 手机操作演示

给店员练习开房、加酒、换酒、收款、存取酒；给老板体验挂账审批、库存留痕和交班核对。**不是正式营业系统。**

## 启动

安装 Node.js 后，在本目录运行 `node server.js`，或 `npm start`。无需安装项目依赖。

- 店员系统：http://localhost:4173
- 后台管理：http://localhost:4173/admin（需要“进入管理后台”权限）
- 手机与电脑连接同一个 Wi-Fi，访问 `http://电脑的局域网IPv4地址:4173`；电脑保持运行。Windows 若询问网络权限，仅按实际需要允许私人网络。
- 页面也可在电脑浏览器缩窄窗口后体验。
- 测试：`npm test`。使用 Node 内置测试框架，无第三方生产依赖。
- 当前 Codex 环境未提供 npm 命令，本次使用 `pnpm --package=npm dlx npm test` 临时调用 npm，未修改项目依赖。

## 已提供的操作

1. 房间：9个实际编号，开房（渠道默认线下，可选美团／抖音；平台券开房费用按0元计收并保留待接入扫码验券接口）、按日期／场次／来源预订（不占当前房态，营业中房间也能排未来场次）、到时每小时提醒、首次配酒水、同一张加单录入多种酒水、套餐及增购酒水换购、按增购数量赠酒水、分笔收钱、结账、挂账和打扫恢复空房。
   房卡有未来预订时显示“已预订”并可在筛选中找到；当前场次仍显示“点这里开房”。标记房间故障／维护时提交文字或照片后立即生效，无需审核；恢复为空房时再次提交证据，并由具备房间恢复审核权限的员工批准。审核本人提交的恢复申请还必须有“允许审核本人申请”权限。异常及待恢复审核的房间都不能开房或预订。
2. 存取酒：手机号任意部分或姓名检索；手机号和姓名填一个即可；一次可登记多种酒，取酒时用手机尾号或姓名核对，并支持部分取酒和流水。
3. 我的：提供七种演示身份；岗位说明为管理员（后台总管理）、卓老板（老板）、老板娘（店长）、邵老板（大堂经理）、雄老板（外联经理）、卓益（订房服务专员）、美娇（订房专员）。岗位名称只作说明，具体操作权限由管理员调整；页面还提供练习时间、交班、库存、操作说明和清空重练。
4. 后台管理：使用独立的 `/admin` 入口；拥有“进入管理后台”权限的身份可审核超额赠酒水、特殊差额、挂账回款、房间恢复、库存盘点与客诉／异常恢复，查看挂账签字、开单／预订来源、库存提醒和交班差异。审核人必须拥有对应业务审核权限；审核本人申请时，还必须单独拥有“允许审核本人申请”权限。管理员可在单个身份卡片中调整其他演示身份的具体操作权限，管理员权限固定，变更保存在本机并由业务规则执行。
5. 报表：管理员、老板、店长、财务和收银员可在主导航打开营业报表，按包间汇总截图中的消费、支付、赠送、酒水打数、合计和备注字段。
6. 页面配色：在“我的”中选择日间、夜间或自动；自动模式按演示日出06:00至19:00为日间，其余时间为参考样图的黑金夜间模式，选择在刷新后保留。
7. “我的”提供采购、支出／报销和客诉／异常记录；采购自动关联支出，客诉可指派负责人并在每天14:00提示未完成事项。管理页支持按员工补录订房／增购、单卡片具体权限调整，以及酒水／消耗品分开库存管理。

默认练习时间为当天20:00，不自动走时。可在“我的”调整时间测试18:00、02:00和挂账逾期。V01/V02/V03为小房，V05/V06为中房；房卡、开房、预订、报表等页面统一显示该房型。
配色使用设备实际时间，不受练习时间影响；夜间模式覆盖所有页面、弹窗及报表，签名区保留浅底以看清笔迹。夜间配色基准为深炭黑`#141210`、鎏金`#C9A227`和米白文字`#E8E0D0`，主按钮使用金属渐变。

## 数据与限制

- 全部操作均为模拟，收款靠手工登记，不连接银行、支付平台、钉钉或外部通知。页面与弹窗持续标识演示。
- 所有练习数据（含虚构手机号、签字）保存在当前浏览器的 localStorage，键名 `jbhh-demo-v1`。恢复演示会清空本机练习。浏览器清理数据也会丢失记录。
- `database/` 已提供 PostgreSQL 关系型结构、当前主数据和金山营业报表导入暂存区；静态演示尚未连接该数据库。
- 各手机、浏览器、来源地址独立。localhost 和局域网IP也是不同来源。没有多人同步、服务器账本、真实认证、备份、可靠跨标签并发控制或离线重新加载保障。
- 已加载页面可本机操作；不包含正式版断网队列、恢复联网冲突处理。不要将其用于营业。
- 开房酒水已补充“饮料、红青岛、蓝妹（罐装）”，并将“金百威”显示名改为“黑金百威”。开房赠饮不再提供手工半打入口；啤酒加购支持单支、半打和整打，半打价格为整打的一半。饮料、汽水仍只按单支加购。
- 开房选择“饮料”时，先在开房表单内直接配好实际酒水种类与总支数；开房后的调整再使用“换酒水”。套餐、付费增购和已经赠送的酒水均可按支1:1换，原收费金额不变。同一种酒水每增购24支，开单员／服务员可赠对应酒水半打；超额赠送进入老板／店长确认，赠送金额为0。
- 加酒水时类别统一显示为“啤酒”，商品下拉仍同时提供普通啤酒和高端啤酒；饮料、汽水、瓶装水分别列出。
- “收钱”只登记最近一笔未收增购；没有增购待收时登记开房费用，房间继续营业。“结账”汇总所有未收费用，完成后房间才转为待清洁；结账时少收的差额默认记录为免零金额，也可填写“特殊情况”并交有权限员工审核。审核本人申请时还需“允许审核本人申请”权限。两处均支持添加多笔付款，并可选择微信、支付宝、现金、美团、抖音。
- 瓶装水单支2元。所有演示身份都可从结账入口申请挂账；手机号或顾客姓名至少填写一个，备注必填，后台同时保留挂账经办、开单员工、预订员工和预订方式。已经收取的金额不会重复挂账。
- 演示使用基线已明确或本轮用户补充的饮品价格和2种套餐配品。未导入治理版 Excel，不虚构其余零食和香烟价格；果盘、花生瓜子不单独销售、不管理库存。
- 交班演示以本轮练习累计实收核对，不代表正式日结或班次切账；挂账回款登记后需有回款审核权限的员工批准，批准后才扣减欠款并计入实收；本人审核还需单独的自审权限。
- 未实现退款、并房、会员营销、存酒转赠／过期、价格维护、真实推送、自动定时催收。逾期提示是老板页上的演示提示。
- 预订提醒在演示页面内显示，不会向手机或钉钉外发；练习时间手动前进后可验证第1次、第2次等每小时提醒。

新会话或交付接手先读 [交付说明](./交付说明.md)。详细操作见 [店员练习手册](./店员练习手册.md)，验证记录见 [验收清单](./验收清单.md)。

## 代码结构

- `rules.js`：纯业务规则和克隆后提交的事务函数；所有金额使用整数分，失败不回写原状态。
- `app.js`：界面、表单、手写签名、本机保存。每份提交使用独立操作编号，重复编号不再次入账。
- `theme.js`：日夜配色、日出06:00至19:00自动切换、我的页三档选择和偏好持久化（独立键`jbhh-appearance-v1`），重置练习数据不清除配色偏好。
- `style.css` / `index.html` / `admin.html`：手机优先的店员入口与独立后台入口，共用业务状态和配色。
- `server.js`：仅提供白名单静态文件，不读写业务数据；默认端口4173，可用 PORT 环境变量修改。
- `database/`：PostgreSQL 16 建表、基础主数据、金山日报／支出表暂存区、字段映射和 CSV 表头模板。
- `rules.test.js` / `theme.test.js` / `database.test.js` / `entry.test.js`：48项业务测试、4项配色测试、5项数据库契约测试和1项入口契约测试，共58项。

正式版需把规则校验放在服务端，以数据库事务保证房态、库存、存酒强一致，补充真实身份、审计、备份恢复、订单版本、通知重试及按营业日的报表。
